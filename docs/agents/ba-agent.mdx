The **Business Analyst (BA) Agent** is the first point of contact for every requirement submitted to Revolte. Its job is to understand your intent, clarify ambiguities, and translate high-level requests into a format that the implementation engine can execute with precision.

## Core Responsibilities

The BA Agent performs several critical tasks during the [Requirement Analysis](/docs/build/code-generation-flow#flow-stages) phase:

<CardGroup cols={2}>
  <Card title="Intent Clarification" icon="magnifying-glass">
    Analyzes your prompt to identify missing details, such as edge cases, validation rules, or specific API requirements.
  </Card>
  <Card title="Context Mapping" icon="map">
    Determines which parts of your application and repository are affected by the request.
  </Card>
  <Card title="Requirement Refinement" icon="wand-magic-sparkles">
    Expands vague prompts into detailed, actionable requirements that include acceptance criteria.
  </Card>
  <Card title="Implementation Safety" icon="shield-check">
    Checks whether the requested change conflicts with existing system behavior or repository patterns.
  </Card>
</CardGroup>

## Working with the BA Agent

The best way to work with the BA Agent is to provide clear, behavior-focused requirements. 

### What the BA Agent looks for:
- **Desired Outcome**: "What should happen?"
- **Input/Output**: "What data is involved?"
- **Constraints**: "Are there any specific rules or permissions?"
- **Validation**: "How do we know it works?"

<Tip title="Pro Tip: Be Specific">
  Instead of saying "Add auth," try "Add JWT authentication to the user profile API using a 401 response for invalid tokens." The BA Agent will use this detail to create a more accurate implementation plan.
</Tip>

## How the BA Agent Helps Reviewers

Because the BA Agent understands the *intent* behind a change, it automatically generates the [Implementation Summary](/docs/build/pre-build-workflows#code-review-and-summarization) found in your pull requests. This helps your team understand not just what changed, but why the BA Agent made those specific implementation choices.
