Observe helps you understand what happened during a build or deployment and how the application behaves after release. Use it immediately after deployments, during incident response, or when validating whether a change is healthy.

## Before you start

You need:

- An active workspace
- A deployed application or recent deployment attempt
- Access to the application logs or metrics view

## Pick the right signal

Start with the question you are trying to answer.

| Question | Start with | Then check |
| --- | --- | --- |
| Did deployment finish correctly? | Activity Timeline | Logs |
| Why did the build or release fail? | Logs | Activity Timeline |
| Is the live system healthy? | Metrics | Logs |
| Did a release cause a regression? | Metrics | Logs and Past Deployments |

## Investigation workflow

<Steps>
  <Step title="Open the application">
    Select the workspace, project, and application you want to inspect.
  </Step>

  <Step title="Choose the signal">
    Use activity for release sequence, logs for exact execution detail, and metrics for system health over time.
  </Step>

  <Step title="Inspect logs">
    Look for failed steps, request traces, runtime errors, missing variables, or warning patterns around the incident timestamp.
  </Step>

  <Step title="Inspect metrics">
    Check latency, error rate, CPU, memory, and delivery metrics to understand scope and impact.
  </Step>

  <Step title="Decide next action">
    Retry deployment, fix configuration, open a new Build request, roll back to a stable deployment, or continue monitoring.
  </Step>
</Steps>

## Example: release verification

After deploying a new API endpoint:

1. Open Activity Timeline and confirm the deployment completed.
2. Open logs and check for startup or request errors.
3. Open metrics and compare error rate and latency before and after the release.
4. If the release caused failures, inspect Past Deployments for a rollback target.

## What to watch after release

- Error rate changes
- Latency spikes
- Failed health checks
- Memory or CPU increases
- Repeated runtime warnings
- Deployment duration changes
