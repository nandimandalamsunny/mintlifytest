---
title: "How Deploy Works"
description: "Understand how Deploy moves approved code into managed, observable runtime environments."
---

Deploy is Revolte's delivery layer. It moves approved code from a repository change to a running application across controlled environments.

Traditional deployment work often requires separate CI/CD configuration, cloud setup, environment management, rollback tooling, and log inspection. Deploy brings those concerns into one release workflow so developers can ship without manually stitching together infrastructure and pipeline systems.

## What Deploy manages

Deploy manages:

- Environment setup
- Branch-to-environment mapping
- Automated deployment pipelines
- Preview deployments
- Deployment activity
- Deployment history
- Rollback workflows
- Release visibility through logs and metrics

## How it works

<Steps>
  <Step title="Receive a trigger">
    A deployment starts from a merge, branch update, manual action, or preview request.
  </Step>

  <Step title="Build the artifact">
    Revolte packages the application using the configured framework, root directory, build command, and runtime settings.
  </Step>

  <Step title="Prepare the environment">
    Environment variables, secrets, services, and runtime configuration are applied for the target environment.
  </Step>

  <Step title="Release the application">
    Revolte deploys the new version and records the deployment timeline.
  </Step>

  <Step title="Verify and observe">
    Logs, activity, metrics, and history help the team confirm whether the release is healthy.
  </Step>
</Steps>

## Key objects

| Object | What it represents |
| --- | --- |
| Application | The deployable unit managed by Revolte |
| Environment | A release target such as preview, QA, staging, or production |
| Deployment | A release of a specific application version to an environment |
| Activity | A chronological timeline of events in a deployment |
| Past deployment | A historical release record used for audit and rollback |

## Deployment triggers

Deployments can be triggered by:

- Pull request merges
- Branch updates
- Manual dashboard actions
- Preview deployment requests

## When to use Deploy

Use Deploy when you need to:

- Release approved code to a target environment
- Validate a feature branch through a preview
- Promote a release from staging to production
- Apply new runtime configuration
- Inspect a failed release
- Roll back to a stable version
