This guide explains how to configure a Web service with both a Storage Bucket and a Cache in Revolte, covering Repo Preference and Environment Settings. Visual references are provided for each step.

## Prerequisites

Before you configure this preset, make sure you have:

- A Revolte workspace with an application created
- Repository access for the target application
- Permission to edit YAML configuration and commit changes
- Environment-specific values for QA, staging, production, and preview

## Step 1: Choose a Preset

Select the **Web service + Storage Bucket + Cache** preset to deploy a backend service with object storage and cache support.

![Choose Web Service + Storage Bucket + Cache Preset](/images/guides/repo_preference/preset-12.png)

- **Web service + Storage Bucket + Cache**: Backend service with object storage and cache (e.g., APIs with file uploads and fast access).

## Step 2: Repo Preference

Configure repository interaction for your service:

- **Application and branch setting**: Choose the branch and framework for your backend service.
- **Agent workflow**: Enable to automate developer workflows.
- **Pre-build workflow**: Enable code review and summarization before builds.
- **Pipeline**: Configure code quality and test suite steps.
- **Build and deployment workflow**: Enable to automate build and deployment for your service.

## Step 3: Environment Settings

After repo preferences, configure environment-specific settings for your service.

### 3.1 Environment Settings Overview

![Environment Settings Overview](/images/guides/environment_settings/envsettings-2.png)

In the Environment Settings panel, select the **Web service**, **Storage Bucket**, and **Cache** tabs to configure backend, storage, and cache details for each environment (QA, Staging, Production, Preview).

#### Fields in Web Service Tab:
- **Service Name**: Unique name for the service (e.g., storage-cache-api)
- **Entry Point**: Main file to launch (e.g., index.js)
- **Specifications**: Define CPU, memory, and storage requirements
- **CPU & Memory**: Set resource limits for the service
- **Storage Value**: Specify disk storage allocation
- **Properties**:
  - **Health Endpoint**: Path for health checks (e.g., /health)
  - **Port**: Port number for the service (e.g., 8080)
- **Pre Script**: List of scripts to run before service starts (empty by default)
- **Load Balancer Mode**: Choose between dedicated or shared load balancer
- **Insights**: Select metrics for CPU, swap, memory, and disk
- **Variables**: Set environment variables (e.g., STORAGE_BUCKET_URL, CACHE_URL)

#### Fields in Storage Bucket Tab:
- **Bucket Name**: Name for your storage bucket
- **Region**: Storage region (e.g., us-east-1)
- **Access Policy**: Public or private access
- **Lifecycle Rules**: Configure object expiration or transitions
- **Storage Class**: Standard, infrequent access, etc.
- **Variables**: Environment variables for storage access

#### Fields in Cache Tab:
- **Cache Type**: e.g., Redis, Memcached
- **Cache Name**: Name for your cache instance
- **Max Memory**: Maximum memory allocation for the cache
- **Eviction Policy**: How cache evicts entries (e.g., LRU, LFU)
- **Variables**: Environment variables for cache connection

### 3.2 Example: Staging Environment

![Staging Web Service + Storage Bucket + Cache Example](/images/guides/environment_settings/envsettings-12-1.png)

- **Service Name**: storage-cache-api
- **Entry Point**: index.js
- **Specifications**: Set as needed for your workload
- **CPU & Memory**: Configure based on expected usage
- **Storage Value**: Allocate disk space
- **Properties**:
  - **Health Endpoint**: /health
  - **Port**: 8080
- **Pre Script**: (empty)
- **Load Balancer Mode**: dedicated
- **Insights**: idle, system, user, swap usage, total/free memory, disk used/total/free
- **Variables**: STORAGE_BUCKET_URL, CACHE_URL

![Staging Storage Bucket Example](/images/guides/environment_settings/envsettings-12-2.png)

- **Bucket Name**: revolte-bucket
- **Region**: us-east-1
- **Access Policy**: private
- **Lifecycle Rules**: Set as needed for object management
- **Storage Class**: Standard
- **Variables**: Set storage access variables for your app

![Staging Cache Example](/images/guides/environment_settings/envsettings-12-3.png)

- **Cache Type**: Redis
- **Cache Name**: revolte-cache
- **Max Memory**: 512MB
- **Eviction Policy**: LRU
- **Variables**: Set cache connection variables for your app

#### How to Configure Each Field
1. Fill in all required fields for Web Service, Storage Bucket, and Cache tabs as described above.
2. Repeat for each environment tab (QA, Staging, Production, Preview) as needed.

### Commit Details

At the bottom of the configuration panel, you will find **Commit Details**:
- **File Name**: The YAML file to be committed (e.g., revolte.yml)
- **Commit Message**: Enter a descriptive message for your changes.
- **Choose Branch**: Select the branch to commit the configuration to.
- **Commit**: Save and apply your configuration.
- **Skip & deploy**: Skip commit and proceed to deployment (not recommended for production).

> **Tip:** Always review your configuration and commit with a clear message to maintain traceability.

For more details, refer to the [configuration guide overview](/docs/guides/overview).
