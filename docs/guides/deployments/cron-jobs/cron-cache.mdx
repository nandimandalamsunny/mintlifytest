---
title: "Cron with Cache"
description: "Configure repository preferences and environment settings for a cron service with cache."
---

This guide walks through configuring a Cron service with an attached Cache in Revolte step by step.

<Steps>
  <Step title="Choose a Preset">
    ![Choose Cron + Cache Preset](/images/guides/repo_preference/preset-9.png)

    The preset chooser shows a grid of service options. The **Cron + Cache** tile is highlighted. Click **Cron + Cache** to continue.
  </Step>

  <Step title="Repo Preference">
    The Repo Preference tab is identical across all service presets. See [Repository Preference](/docs/guides/overview#repository-preference) for a full walkthrough of each setting.
  </Step>

  <Step title="Cron — Environment Settings">
    ![Cron tab — QA environment](/images/guides/environment_settings/envsettings-9.png)

    The **QA** environment tab is selected. The left sidebar shows **Cron**, **Cache**, and **Variables** under Build & deployment workflow. The center panel shows the Cron form:

    - **Service Name** — Enter a unique identifier for this cron job (e.g., `cron_service`).
    - **Entry Point** — The main file executed on each cron run (e.g., `index.js`).
    - **Specifications**
      - **CPU & Memory** — Choose a compute tier for this job (e.g., `2 CPU and 1 GB Memory`).
      - **Storage value** — Disk space in GB allocated to the job (e.g., `30`).
    - **Properties**
      - **Scheduler** — Enter a cron expression to set when the job runs (e.g., `cron(* 20 * ? *)`).
    - **Pre Script** — Commands to run before the job executes. Click **+ Add** to add a script.
    - **Insights** — Select system metrics to monitor:
      - **Cpu** — Options: idle, user, system.
      - **Swap** — Options: swap usage.
      - **Memory** — Options: total memory used, free memory.
      - **Disk** — Options: disk used, disk total, disk free.
  </Step>

  <Step title="Cache — Environment Settings">
    ![Cache tab — QA environment](/images/guides/environment_settings/envsettings-9-1.png)

    The **QA** environment tab is selected with the **Cache** tab active. The left sidebar shows **Cron**, **Cache**, and **Variables**. The center panel shows the Cache form:

    - **Service Name** — Enter a unique identifier for this cache instance (e.g., `my_cache`).
    - **Specifications**
      - **CPU & Memory** — Choose a resource tier that matches your caching needs (e.g., `2 CPU and 1 GB Memory`).
  </Step>

  <Step title="Variables & Secrets">
    ![Variables & Secrets tab — QA environment](/images/guides/environment_settings/envsettings-9-2.png)

    The **QA** environment tab is selected with the **Secrets** sub-tab active. The left sidebar shows **Cron**, **Cache**, and **Variables**. The center panel shows:

    - **Secret Engine** — **Revolte secrets** is the built-in provider for storing encrypted key-value pairs.
    - **Add Secrets** button — Click to add a secret. Enter a key (e.g., `DATABASE_URL`) and its value (e.g., a connection string or API key).
    - Secrets appear as rows in the table once added. The table is empty until the first secret is created.
  </Step>

  <Step title="Commit">
    At the bottom of the panel, fill in the **Commit Details**:

    - **File Name** — The configuration file to create or update in your repository (e.g., `revolte.yml`).
    - **Commit Message** — A short description of what you configured (e.g., `Add cron service with cache`).
    - **Choose Branch** — The branch where the configuration file will be committed.

    Click **Commit** to save the configuration to your repository, or **Skip & deploy** to deploy immediately without committing.
  </Step>
</Steps>

> **Tip:** Always commit with a clear message before deploying to keep a traceable configuration history.
