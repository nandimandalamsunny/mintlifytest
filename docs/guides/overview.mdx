---
title: "Guide Overview: Configuring Your Application"
---

After creating your application with Revolte, the next step is configuration. This guide covers how to set up repository preferences and environment settings for each service, ensuring your deployments are tailored to your workflow and infrastructure needs.

## Prerequisite

Before proceeding, make sure you have completed the application creation process. If not, start with the [Quick Start guide](../../build/quick-start).

## What Comes Next

Once your application is created, configuration is divided into two main areas:

<Steps>
  <Step title="Repository Preference">
    Define how Revolte interacts with your code repository. Set up branch mappings, enable agent workflows, and configure pre-build steps to match your team's development process.
  </Step>
  <Step title="Environment Settings">
    Specify environment variables, secrets, and deployment targets for each service. This ensures that every environment—production, staging, QA, and preview—has the correct configuration and access controls.
  </Step>
</Steps>

## Why Configuration Matters

- **Consistency:** Standardize how code moves from development to deployment across all services.
- **Security:** Control access and manage secrets for each environment.
- **Flexibility:** Adapt workflows to fit your team's branching and release strategies.

## Next Steps

- Review and adjust repository preferences for your application.
- Set up environment variables and secrets for each deployment target.
- Continue to the next guide for detailed walkthroughs of each configuration option.
