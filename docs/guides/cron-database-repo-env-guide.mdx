This guide explains how to configure a Cron service with an attached Database in Revolte, covering both Repo Preference and Environment Settings. Visual references are provided for each step.

## Prerequisites

Before you configure this preset, make sure you have:

- A Revolte workspace with an application created
- Repository access for the target application
- Permission to edit YAML configuration and commit changes
- Environment-specific values for QA, staging, production, and preview

## Step 1: Choose a Preset

Select the **Cron + Database** preset to automate scheduled tasks with database read/write support.

![Choose Cron + Database Preset](/images/guides/repo_preference/preset-5.png)

- **Cron + Database**: Schedule tasks with database read/write support (e.g., periodic data syncs, reporting jobs).
- Other options include Web app, Web service, and combinations with storage or cache.

## Step 2: Repo Preference

Configure repository interaction for your cron service with a database:

- **Application and branch setting**: Choose the branch and framework for your scheduled job.
- **Agent workflow**: Enable to automate developer workflows.
- **Pre-build workflow**: Enable code review and summarization before builds.
- **Pipeline**: Configure code quality and test suite steps.
- **Build and deployment workflow**: Enable to automate build and deployment for your service.

## Step 3: Environment Settings

After repo preferences, configure environment-specific settings for your cron service with a database.

### 3.1 Environment Settings Overview

![Environment Settings Overview](/images/guides/environment_settings/envsettings-5.png)

In the Environment Settings panel, select the **Cron** and **Database** tabs to configure scheduled job and database details for each environment (QA, Staging, Production, Preview).

#### Fields in Cron Tab:

- **Service Name**: Unique name for the cron job (e.g., data-sync-cron)
- **Entry Point**: Main file to launch (e.g., index.js)
- **Schedule**: Cron expression defining when the job runs (e.g., `0 0 * * *` for daily at midnight)
- **Specifications**: Define CPU, memory, and storage requirements
- **CPU & Memory**: Set resource limits for the job
- **Storage Value**: Specify disk storage allocation
- **Properties**:
  - **Job Timeout**: Maximum allowed runtime for the job
  - **Retries**: Number of retry attempts on failure
- **Pre Script**: List of scripts to run before the job starts (empty by default)
- **Variables**: Set environment variables (e.g., DATA_SOURCE_URL)

#### Fields in Database Tab:

- **Database Type**: e.g., PostgreSQL, MySQL
- **Database Name**: Name for your database
- **User/Password**: Credentials for database access
- **Connection String**: Auto-generated or custom
- **Storage**: Disk allocation for the database
- **Backup & Restore**: Options for data safety
- **Variables**: Environment variables for database connection

#### How to Configure Each Field

1. **Service Name**: Enter a unique, descriptive name for the cron job.
2. **Entry Point**: Specify the main file to start the job.
3. **Schedule**: Enter a valid cron expression for the job schedule.
4. **Specifications**: Define CPU, memory, and storage needs.
5. **CPU & Memory**: Set resource limits for performance and cost control.
6. **Storage Value**: Allocate disk space for the job.
7. **Properties**:
   - **Job Timeout**: Set the maximum allowed runtime.
   - **Retries**: Set the number of retry attempts on failure.
8. **Pre Script**: Add any scripts to run before the job starts (optional).
9. **Variables**: Add environment variables required by your job.
10. **Database Tab**: Fill in database type, name, credentials, storage, and backup options.

#### How to Configure Each Tab

- **QA**: Use for internal testing. Set variables and properties to mimic production, but with test data or endpoints.
- **Staging**: Mirror production settings for final validation.
- **Production**: Set all variables and properties for live jobs. Optimize resources and enable monitoring.
- **Preview**: Use for feature branches. Set variables to point to test endpoints or mock services.

### Commit Details

At the bottom of the configuration panel, you will find **Commit Details**:

- **File Name**: The YAML file to be committed (e.g., revolte.yml)
- **Commit Message**: Enter a descriptive message for your changes.
- **Choose Branch**: Select the branch to commit the configuration to.
- **Commit**: Save and apply your configuration.
- **Skip & deploy**: Skip commit and proceed to deployment (not recommended for production).

> **Tip:** Always review your configuration and commit with a clear message to maintain traceability.

For more details, refer to the [configuration guide overview](/docs/guides/overview).
