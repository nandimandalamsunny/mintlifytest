Integrations connect Revolte to the systems your team already uses for source control, deployment, alerts, and operational visibility.

## Before you connect

Prepare these details before adding an integration:

- Administrator access to the external tool
- Permission to install apps, create tokens, or approve OAuth access
- The workspace, project, or repository Revolte should connect to
- Any security review requirements your organization applies to third-party access

## Integration categories

| Category | Typical use |
| --- | --- |
| Source control | Connect repositories, create branches, and open pull requests |
| Project management | Link requirements, issues, and delivery status |
| Cloud providers | Configure infrastructure targets and runtime credentials |
| Collaboration | Route deployment, build, and incident notifications |
| Observability | Export or correlate logs, metrics, and alerts |

## Operating guidance

- Grant the narrowest permissions that support the workflow.
- Connect production systems only after testing the integration in a lower-risk workspace or environment.
- Rotate credentials according to your internal security policy.
- Review integration access when team ownership or repository ownership changes.
