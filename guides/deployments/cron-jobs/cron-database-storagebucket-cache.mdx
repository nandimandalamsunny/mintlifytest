---
title: "Cron with Database, Storage Bucket & Cache"
description: "Configure repository preferences and environment settings for a cron service with database, storage, and cache."
---

This guide explains how to configure a Cron service with Database, Storage Bucket, and Cache in Revolte, covering Repo Preference and Environment Settings. Visual references are provided for each step.

<Steps>
  <Step title="Choose a Preset">
    ![Choose Cron + Database + StorageBucket + Cache Preset](/images/guides/repo_preference/preset-15.png)

    The preset chooser shows a grid of service options. The **Cron + Database + StorageBucket + Cache** tile is highlighted. Click **Cron + Database + StorageBucket + Cache** to continue.
  </Step>

  <Step title="Repo Preference">
    The Repo Preference tab is identical across all service presets. See [Repository Preference](/guides/overview#repository-preference) for a full walkthrough of each setting.
  </Step>

  <Step title="Cron — Environment Settings">
    ![Cron tab — QA environment](/images/guides/environment_settings/envsettings-15.png)

    The **QA** environment tab is selected. The left sidebar shows **Cron**, **Database**, **Storage Bucket**, **Cache**, and **Variables** under Build & deployment workflow. The center panel shows the Cron form:

    - **Service Name** — Enter a unique identifier for this cron job (e.g., `cron_service`).
    - **Entry Point** — The main file executed on each cron run (e.g., `index.js`).
    - **Specifications**
      - **CPU & Memory** — Choose a compute tier for this job (e.g., `2 CPU and 1 GB Memory`).
      - **Storage value** — Disk space in GB allocated to the job (e.g., `30`).
    - **Properties**
      - **Scheduler** — Enter a cron expression to set when the job runs (e.g., `cron(* 20 * ? *)`).
    - **Pre Script** — Commands to run before the job executes. Click **+ Add** to add a script.
    - **Insights** — Select system metrics to monitor:
      - **Cpu** — Options: idle, user, system.
      - **Swap** — Options: swap usage.
      - **Memory** — Options: total memory used, free memory.
      - **Disk** — Options: disk used, disk total, disk free.
  </Step>

  <Step title="Database — Environment Settings">
    ![Database tab — QA environment](/images/guides/environment_settings/envsettings-15-1.png)

    The **QA** environment tab is selected with the **Database** tab active. The left sidebar shows **Cron**, **Database**, **Storage Bucket**, **Cache**, and **Variables**. The center panel shows the Database form:

    - **Service Name** — Enter a unique identifier for this database instance (e.g., `my_database`).
    - **Specifications**
      - **Engine Type** — Select the database engine to use (e.g., MySQL, PostgreSQL).
      - **CPU & Memory** — Choose a resource tier that matches your workload (e.g., `2 CPU and 1 GB Memory`).
    - **Storage value** — Disk space in GB allocated to the database (e.g., `30`).
  </Step>

  <Step title="Storage Bucket — Environment Settings">
    ![Storage Bucket tab — QA environment](/images/guides/environment_settings/envsettings-15-2.png)

    The **QA** environment tab is selected with the **Storage Bucket** tab active. The left sidebar shows **Cron**, **Database**, **Storage Bucket**, **Cache**, and **Variables**. The center panel shows the Storage Bucket form:

    - **Service Name** — Enter a name for the storage bucket service.
    - **Configurations**
      - **Bucket Name** — Enter a name for the storage bucket.
      - **Bucket Versioning** — Toggle to enable versioning.
      - **Enable Public Access** — Toggle to allow public access.
    - **Cors Rules** — Shown as empty. Click **+ Add** to add CORS rules.
  </Step>

  <Step title="Cache — Environment Settings">
    ![Cache tab — QA environment](/images/guides/environment_settings/envsettings-15-3.png)

    The **QA** environment tab is selected with the **Cache** tab active. The left sidebar shows **Cron**, **Database**, **Storage Bucket**, **Cache**, and **Variables**. The center panel shows the Cache form:

    - **Service Name** — Enter a unique identifier for this cache instance (e.g., `my_cache`).
    - **Specifications**
      - **CPU & Memory** — Choose a resource tier that matches your caching needs (e.g., `2 CPU and 1 GB Memory`).
  </Step>

  <Step title="Variables & Secrets">
    ![Variables & Secrets tab — QA environment](/images/guides/environment_settings/envsettings-15-4.png)

    The **QA** environment tab is selected with the **Secrets** sub-tab active. The left sidebar shows **Cron**, **Database**, **Storage Bucket**, **Cache**, and **Variables**. The center panel shows:

    - **Secret Engine** — **Revolte secrets** is listed as the available provider.
    - **Add Secrets** button — Click to add a key-value secret pair.
    - The key-value table is empty (**No data available**).
  </Step>

  <Step title="Commit">
    At the bottom of the panel, fill in the **Commit Details**:

    - **File Name** — e.g., `revolte.yml`.
    - **Commit Message** — Enter a descriptive message.
    - **Choose Branch** — Select the branch to commit to.

    Click **Commit** to save, or **Skip & deploy** to go directly to deployment.
  </Step>
</Steps>

> **Tip:** Always commit with a clear message before deploying to keep a traceable configuration history.
