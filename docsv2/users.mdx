User management controls who can configure projects, deploy services, approve production releases, manage secrets, and view operational data.

## Roles

| Role | Best for | Permissions |
| --- | --- | --- |
| Owner | Workspace administrators | Billing, members, all projects, production policy. |
| Admin | Platform team | Projects, repositories, environments, services, users. |
| Developer | Service owners | Deployments, logs, metrics, non-production settings. |
| Reviewer | Engineering leads and approvers | Review gates, approvals, deployment history. |
| Viewer | Support, QA, auditors | Read-only access to projects and observability. |

## Invite flow

<Steps>
  <Step title="Open workspace users">
    Go to Workspace Settings and select Users.
  </Step>
  <Step title="Invite by email">
    Enter the teammate's work email and choose a default role.
  </Step>
  <Step title="Scope project access">
    Limit access to the projects and environments the user needs.
  </Step>
  <Step title="Require MFA for sensitive roles">
    Enforce multi-factor authentication for owners, admins, and production approvers.
  </Step>
</Steps>

## Permission areas

| Area | Sensitive actions |
| --- | --- |
| Projects | Create, archive, change ownership. |
| Repositories | Connect provider, change branch mapping. |
| Environments | Edit production variables, approvals, promotion rules. |
| Services | Change ports, scaling, deploy strategy, dependencies. |
| Secrets | Create, rotate, reveal metadata, delete. |
| Deployments | Promote, pause, roll back, override gates. |

<Warning>
  Restrict production secret editing to a small group. Most developers only need deployment and observability access.
</Warning>
