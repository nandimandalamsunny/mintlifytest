Revolte is an AI-native software delivery platform for turning engineering intent into deployed, observable software. It connects build automation, deployment orchestration, runtime telemetry, and feedback into one delivery loop.

## Delivery loop

Revolte models delivery as a continuous system:

| Stage   | What Revolte does                                                                                               |
| ------- | --------------------------------------------------------------------------------------------------------------- |
| Intent  | Reads commit messages, pull requests, diffs, tickets, and developer prompts to understand the requested change. |
| Build   | Detects the project shape, runs configured build steps, and packages deployable services.                       |
| Review  | Scores deployment risk and applies manual or automated review gates.                                            |
| Deploy  | Releases services with rolling, blue/green, or canary strategies.                                               |
| Observe | Streams logs, metrics, and AI-powered anomalies for the running deployment.                                     |
| Improve | Uses runtime data to tune future build, deploy, and review decisions.                                           |

## How teams use Revolte

Developers use Revolte to ship changes without hand-stitching CI, infrastructure, deployment history, and logs. Platform teams use the same system to standardize delivery policies, environment scoping, rollback controls, and service configuration across projects.

<Info>
  Revolte is built for technical teams. These docs assume you are configuring repositories,
  services, environments, and deployment workflows directly.
</Info>

## Typical implementation path

<Steps>
  <Step title="Create a project">
    Define the product boundary that owns repositories, environments, services, and permissions.
  </Step>
  <Step title="Connect a repository">
    Authorize Revolte to read source code, create deployment metadata, and open review workflows.
  </Step>
  <Step title="Declare services">
    Add web applications, APIs, workers, databases, caches, storage, and secrets to the project.
  </Step>
  <Step title="Deploy and observe">
    Release to preview, staging, or production, then inspect logs, metrics, and AI insights.
  </Step>
</Steps>
