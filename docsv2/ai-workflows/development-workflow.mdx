Development workflows define how Revolte reacts to repository activity. A workflow can summarize pull requests, score delivery risk, run checks, require approval, or deploy to preview automatically.

## Git events

| Event | Typical workflow |
| --- | --- |
| Pull request opened | Summarize intent, identify affected services, deploy preview. |
| Commit pushed | Refresh risk score and rerun validation. |
| Review approved | Unlock staging deployment or auto-merge if policy allows. |
| Main branch updated | Deploy staging or begin production promotion. |

## Risk scoring inputs

| Input | Example risk signal |
| --- | --- |
| File changes | Database migration, auth logic, payment code, infrastructure config. |
| Service criticality | Public API and production database changes score higher. |
| Test coverage | Missing tests for changed surface increases review requirement. |
| Runtime history | Recent incidents increase gate strictness. |

## Configure review gates

<CodeBlock language="yaml" filename="revolte.yaml">
{`aiWorkflows:
  development:
    pullRequests:
      summarize: true
      riskScore: true
      previewDeployments: true
    gates:
      lowRisk:
        autoMerge: true
        maxRiskScore: 35
      production:
        requiredApprovals: 2
        requirePassingInsights: true`}
</CodeBlock>

<Warning>
  Do not enable auto-merge until branch protection, required checks, and ownership rules are configured in the Git provider.
</Warning>

## Workflow steps

<Steps>
  <Step title="Connect repository events">
    Install the provider app and allow Revolte to receive pull request and branch events.
  </Step>
  <Step title="Map services">
    Ensure each service in revolte.yaml points to the correct root directory.
  </Step>
  <Step title="Define risk policy">
    Configure thresholds, required approvals, and production gates.
  </Step>
  <Step title="Validate on a pull request">
    Open a low-risk change and confirm the summary, score, checks, and preview behavior.
  </Step>
</Steps>
