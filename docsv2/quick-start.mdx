Use this guide to deploy a service from a repository into a Revolte environment. You will install the CLI, authenticate, initialize configuration, and run the first deployment.

## Requirements

| Requirement | Minimum |
| --- | --- |
| Node.js | 20 or later for JavaScript projects |
| Git | A repository hosted on GitHub, GitLab, or Bitbucket |
| Permissions | Ability to connect the repository and create deployments |
| Revolte account | Workspace access with project creation rights |

<Note>
  Start with a non-production environment for the first deployment. Promote to production after logs and metrics confirm the service is healthy.
</Note>

## Install the CLI

<Tabs>
  <Tab title="npm">
    <CodeBlock language="bash" filename="Terminal">
{`npm install -g revolte
revolte --version`}
    </CodeBlock>
  </Tab>
  <Tab title="Homebrew">
    <CodeBlock language="bash" filename="Terminal">
{`brew tap revolte-dev/tap
brew install revolte`}
    </CodeBlock>
  </Tab>
  <Tab title="curl">
    <CodeBlock language="bash" filename="Terminal">
{`curl -fsSL https://revolte.dev/install.sh | sh
revolte doctor`}
    </CodeBlock>
  </Tab>
</Tabs>

## Deploy the first service

<Steps>
  <Step title="Authenticate">
    Sign in and bind your local session to the workspace that owns the service.

    <CodeBlock language="bash" filename="Terminal">
{`revolte auth login
revolte workspace use acme-platform`}
    </CodeBlock>
  </Step>
  <Step title="Initialize configuration">
    Generate a starter Revolte configuration at the repository root.

    <CodeBlock language="bash" filename="Terminal">
{`revolte init --project commerce --service checkout-api --type web-service`}
    </CodeBlock>
  </Step>
  <Step title="Review the generated file">
    Confirm the build command, start command, port, and target environment.

    <CodeBlock language="yaml" filename="revolte.yaml">
{`version: "1"
project: commerce

services:
  - name: checkout-api
    type: web_service
    source:
      root: apps/checkout-api
      build: npm ci && npm run build
      start: npm run start
    ports:
      - internal: 3000
        public: true
    deploy:
      strategy: rolling
      healthCheck: /healthz

environments:
  staging:
    branch: main
    variables:
      NODE_ENV: production`}
    </CodeBlock>
  </Step>
  <Step title="Deploy to staging">
    Run the deployment and stream logs until the health check passes.

    <CodeBlock language="bash" filename="Terminal">
{`revolte deploy checkout-api --env staging --follow`}
    </CodeBlock>
  </Step>
</Steps>

## Verify the release

After the deploy finishes, check the deployment timeline and runtime health.

| Signal | What to check |
| --- | --- |
| Deployment logs | Build command, artifact upload, service start, health check result |
| Application logs | Startup errors, missing environment variables, request failures |
| Metrics | CPU, memory, latency, request rate, and error rate |
| Insights | AI-detected anomalies or follow-up recommendations |

<Tip>
  Keep the first deploy small. A simple health endpoint and one public route are enough to validate repository access, build settings, service startup, and observability.
</Tip>
