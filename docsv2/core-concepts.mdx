Revolte organizes delivery around a small set of objects. Understanding these terms makes setup, configuration, deployment, observability, and rollback workflows easier to reason about.

## Platform objects

| Concept | Definition | Common owner |
| --- | --- | --- |
| Workspace | The top-level boundary for teams, billing, members, and shared policies. | Platform team |
| Project | A product or system boundary that groups repositories, environments, and services. | Engineering team |
| Repository | The source control connection Revolte reads and deploys from. | Developers |
| Environment | A runtime target such as preview, staging, or production. | DevOps or platform |
| Service | A deployable or managed runtime unit such as an API, web app, database, cache, or cron job. | Service owner |

## Delivery objects

| Object | What it records |
| --- | --- |
| Build | Source revision, build command, generated artifact, and build logs. |
| Deployment | Service version, environment, strategy, health checks, and release status. |
| Review gate | Risk score, required approvals, policy checks, and automation decisions. |
| Insight | AI-generated anomaly, trend, or recommendation based on deployment and runtime data. |

## AI feedback loop

Revolte uses runtime evidence to improve future decisions. A failed health check can tighten risk scoring. A stable canary can shorten future review paths. Repeated memory pressure can suggest scaling or runtime changes.

<Steps>
  <Step title="Analyze intent">
    Revolte extracts the purpose of a change from commits, diffs, pull requests, tickets, or prompts.
  </Step>
  <Step title="Score delivery risk">
    The platform compares the change against service type, environment, recent incidents, and ownership rules.
  </Step>
  <Step title="Apply gates">
    Low-risk changes can continue automatically. Higher-risk changes require review, canary rollout, or manual approval.
  </Step>
  <Step title="Learn from runtime">
    Logs, metrics, rollbacks, and anomaly detections feed future build and deploy recommendations.
  </Step>
</Steps>

<Info>
  The AI loop does not replace code review. It adds context, risk signals, and automation around the review and deployment process.
</Info>

## Example project shape

<CodeBlock language="yaml" filename="revolte.yaml">
{`version: "1"
project: commerce

services:
  - name: storefront
    type: web_application
    source:
      root: apps/storefront
  - name: checkout-api
    type: web_service
    source:
      root: apps/checkout-api
  - name: orders-db
    type: database
    engine: postgres

environments:
  preview:
    branchPattern: pull-request/*
  production:
    branch: main
    approvals:
      required: 2`}
</CodeBlock>
